# 团队开发哲学与核心原则

> 类型：长期记忆 | 修改频率：极低 | 最后更新：2026-05-22

---

## 核心价值观

1. **用户视角优先** — 所有决策以终端用户（宠物主人、托管方）的利益为出发点
2. **简洁优于聪明** — 可维护的代码胜过炫技；可理解的方案胜过精巧
3. **数据模型先行** — 先定义数据结构和类型，再实现 UI；先写文档，再写代码
4. **类型即文档** — TypeScript 严格模式，类型本身就是最好的文档
5. **数据驱动决策** — 用数据说话，不依赖主观臆断

## 开发原则

### 文档 → 测试 → 实现（不可逆顺序）
```
1. 先写文档（PRD、设计稿说明）
2. 再写测试（单元测试）
3. 最后写实现（功能代码）
```

### 提问哲学
- 遇到模糊需求，**必须先提问，禁止假设**
- 每个 Agent 必须主动确认不确定的细节
- 优先查看 `memory/project/` 和 `memory/long-term/` 中的已有记录

### 代码质量基线
- TypeScript：禁止 `any` 类型
- 前端：LCP < 2.5s, FID < 100ms, CLS < 0.1
- 安全：不泄露敏感信息到前端代码或日志

### Agent 间协作准则
- 通过 `workspace/docs/` 下的文件传递交付物
- 通过 `memory/project/` 共享项目状态
- 遇到阻塞 → 写入 `memory/project/known-issues.md`
- 完成任务 → 更新 `memory/project/task-progress.md`

## 禁止事项

| 禁止行为 | 说明 |
|---------|------|
| 编造数据 | 没有数据就标注"需要调研" |
| 假设技术可行性 | 标注为"开放问题" |
| 跳过文档阶段 | 不写文档直接写代码 |
| 硬编码敏感信息 | 密码、Token、API Key 一律走环境变量 |
| 在日志中输出隐私 | 密码、Token、PII 禁止进入日志 |
