# /diagnose — 系统化调试

> 类型：工程技能 | 触发词：`/diagnose`、调试、Bug 修复、报错

---

## 用途

当代码出现 Bug 或运行时错误时，执行系统化调试流程，而非靠直觉猜测。

## 调试流程（必须严格遵循）

### 步骤 1：复现（Reproduce）
- 用最少步骤复现 Bug
- 记录精确的复现路径：做了什么 → 看到了什么 → 和预期的差距
- 如果无法复现 → 先写一条可复现的测试用例

### 步骤 2：最小化（Minimize）
- 删除无关代码，找到最小复现案例
- 二分法定位：注释掉一半代码 → 确认 Bug 在哪一半 → 继续对半

### 步骤 3：假设（Hypothesize）
- 基于复现和代码，提出 1-3 个根因假设
- 每个假设必须可验证
- 排序假设：最可能的先验证

### 步骤 4：插桩（Instrument）
- 添加日志/console.log 验证假设
- 不要用"看代码"代替测量

### 步骤 5：修复（Fix）
- 定位根因后，做最小改动修复
- 不"顺便"重构无关代码

### 步骤 6：回归验证（Regression Check）
- 确认修复后 Bug 不再出现
- 确认没有引入新问题
- 如有测试套件 → 跑全量测试

## 输出格式

```markdown
## Debug 报告：[Bug 简述]

### 1. 复现步骤
1. 步骤 1
2. 步骤 2

### 2. 根因分析
[一句话：什么导致了 Bug]

### 3. 修复方案
[修改了哪个文件、哪几行、为什么]

### 4. 验证结果
- [x] Bug 已修复
- [x] 回归测试通过
```
