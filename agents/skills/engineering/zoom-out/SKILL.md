# /zoom-out — 代码全局视角

> 类型：工程技能 | 触发词：`/zoom-out`、全局视图、代码全景、整体架构

---

## 用途

跳出单文件/单组件的细粒度视角，提供代码库的高层次全局视图。当感到迷失在细节中或需要向他人解释代码结构时使用。

## 工作流

### 步骤 1：扫描全局结构
- 列出所有路由和页面 → `workspace/frontend/src/pages/`
- 列出所有组件 → `workspace/frontend/src/components/`
- 列出数据流的核心节点（Context、localStorage、Hooks）
- 识别模块边界和依赖关系

### 步骤 2：绘制信息架构

```
📱 页面结构
/                         → 品牌首页
├── /bind/:tagId          → 宠物绑定
├── /pet/:tagId           → 宠物主查看页
├── /stay                 → 民宿选择
├── /book/:innId          → 寄养预约
├── /pass/:tagId          → 屏南通行证
├── /host                 → 托管方入口
├── /host/checkin         → 录入宠物
├── /host/update/:petId   → 状态更新
├── /checkin/:tagId       → H5 打卡（占位）
└── /card/:tagId          → 纪念卡（占位）

🗄️ 数据流
localStorage
├── pets/{tagId}          → Pet 对象（名字+照片+挂牌号+状态）
├── updates/{petId}       → StatusUpdate[] 时间线
├── bookings              → 寄养预约记录
└── inns                  → 民宿数据
```

### 步骤 3：标注问题区域
- 🔴 逻辑过载的组件
- 🟡 待提取的重复模式
- 🟢 架构模式亮点（可复用）
- ⚪ 占位/未实现的区域

### 步骤 4：输出全局视图

```markdown
# 代码全局视图

## 路由地图
[路由树 + 每个路由一句话描述 + 状态]

## 组件树（关键路径）
[从 App → Page → Component 的层次]

## 数据流拓扑
[数据从哪里来、经过哪里、到哪里去]

## 问题雷达
[按紧急程度标注问题区域]

## 开发路线建议
[根据当前状态建议下一步应该聚焦的区域]
```

## 规则

- ❌ 不展示代码细节（那不是本次任务的目的）
- ❌ 不提出模糊建议（"应该重构"太模糊）
- ✅ 必须给出可行动的具体建议
- ✅ 必须标注不确定的部分
