# /tdd — 测试驱动开发

> 类型：工程技能 | 触发词：`/tdd`、先写测试、红-绿-重构

---

## 用途

执行标准的 TDD 红-绿-重构循环，确保代码质量。

## TDD 循环（严格顺序，不可跳过）

### 🔴 红（Red）— 写一个失败的测试
1. 确定要验证的行为
2. 先写测试用例（此时实现代码不存在）
3. 运行测试 → 确认测试**失败**（如果通过说明测试写错了）
4. 测试失败的原因必须是"实现还不存在"而非"语法错误"

### 🟢 绿（Green）— 用最小代码让测试通过
1. 编写刚好让测试通过的最小实现
2. 不考虑性能、优雅、架构
3. 只关注"测试变绿"
4. 运行测试 → 确认通过

### 🔵 重构（Refactor）— 优化代码同时保持测试绿色
1. 消除重复代码
2. 改善变量命名
3. 提取工具函数
4. 每次改动后立即运行测试 → 保持绿色
5. 重构过程中测试变红 → 撤销最后一次改动

## 输出格式

```markdown
## TDD 循环：[功能名称]

### 🔴 测试代码
\`\`\`typescript
// 测试内容
\`\`\`

### 🟢 实现代码
\`\`\`typescript
// 实现内容
\`\`\`

### 🔵 重构
[重构了哪些、为什么]
```

## 规则

- ❌ 禁止跳过"红"阶段（没看到测试失败就写实现）
- ❌ 禁止在"绿"阶段过度设计
- ❌ 禁止在测试失败时强行重构
- ✅ 每个循环只验证一个行为
- ✅ 测试失败后，先看失败信息再写实现

## 项目特定注意

- 前端测试框架：Vitest + React Testing Library（如已配置）
- 当前 MVP 阶段可能没有测试套件，此时 TDD 简化为：手写验收标准 → 验证行为 → 实现
- 如果是纯前端组件，可先定义 TypeScript 接口和类型，再写组件实现
