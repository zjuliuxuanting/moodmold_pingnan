# /improve-architecture — 架构深化改进

> 类型：工程技能 | 触发词：`/improve-architecture`、重构架构、代码腐化、整理代码

---

## 用途

扫描现有代码库，发现架构层面的改进机会，防止 AI 编码导致代码熵增。

## 工作流

### 步骤 1：全局扫描
- 遍历 `workspace/frontend/src/` 目录结构
- 识别以下模式：
  - 重复代码块（两个文件实现相同逻辑）
  - 组件过大（单文件 > 300 行）
  - 关注点混合（页面组件中混有 API 调用、状态管理）
  - 魔法数字/硬编码值
  - 未使用的导入/变量/文件

### 步骤 2：对照规范
- 对照 `agents/memory/long-term/conventions.md`
- 对照 `agents/memory/long-term/principles.md`
- 检查是否违反"类型即文档"原则

### 步骤 3：输出改进建议（按影响排序）

```markdown
## 架构改进建议

### 🔴 紧急（影响稳定性和可维护性）
| 问题 | 位置 | 建议 | 工作量 |
|------|------|------|--------|
| ... | ... | ... | ... |

### 🟡 重要（影响开发效率）
| 问题 | 位置 | 建议 | 工作量 |
|------|------|------|--------|

### 🟢 建议（改善代码质量）
| 问题 | 位置 | 建议 | 工作量 |
|------|------|------|--------|
```

### 步骤 4：记录到项目记忆
- 新增技术债务 → `agents/memory/project/known-issues.md` 的技术债务区
- 新增架构决策 → `agents/memory/project/tech-decisions.md`

## 扫描重点（本项目特化）

- React 组件：有无 memo/useCallback 缺失的性能问题
- Tailwind 类名：有无应该 token 化但直接写死颜色/字体的地方
- TypeScript：有无 `any` 类型逃逸
- localStorage：键名是否统一、有无重复键冲突
- 路由：路径是否一致、有无死路由
