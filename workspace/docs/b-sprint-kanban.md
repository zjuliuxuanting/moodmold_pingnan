## 三、任务详解（执行说明）

### T-08 · 数字孪生出图 [`S-B2-003`]

> ⚠️ **前置阻塞**：依赖 A 交付 A-B2-001（非遗挂件素材包），在素材未就绪前可用纯色占位先搭框架。

**产出**：托管方上传照片 → 系统自动叠加挂件 → 宠物主查看页展示出图。

**具体步骤**：
1. 创建挂件叠加工具函数（Canvas API 实现图片叠加）
2. 在 HostUpdatePage 的更新提交中增加自动出图逻辑
3. 在 PetPage 的出图区域展示叠加后的图片
4. 至少准备 2 套挂件占位（可先用纯色 SVG 替代真实挂件素材）
5. /checkin/:tagId H5 打卡页实现景点→挂件联动

**验收**：托管方上传新照片后，宠物主查看页能看到叠加了挂件的出图。

---

### T-04 · 演示脚本校对 [`P-INF-002`]

**产出**：对 A 交付的演示脚本进行技术点审核。

**步骤**：
1. 通读脚本，标记所有涉及"技术实现"的描述
2. 核对每个技术点是否与实际代码一致
3. 标注超出 MVP 范围的、「不可实现」或「误导」的表述
4. 输出修改建议清单

**验收**：脚本中无不准确的技术描述。

---

### T-05 · 依赖检查

**产出**：确认各方依赖就绪情况。

**步骤**：
1. 确认 A-B2-002（Demo 宠物照片）是否可获取
2. 确认 A-B2-001（挂件素材）预计交付时间
3. 确认 A-INF-001（视觉规范）实际交付内容是否完整
