# Moodmold 黑客松交付物说明书

> 版本 v1.2 | 日期：2026-05-22 Day 2 | 基于 v0.3 产品战略
> 本文档定义项目交付物的功能需求和验收标准，不涉及技术实现路径或设计细节。
> 技术选型、视觉规范、目录结构等参见独立的技术决策文档和设计规范文档。

---

## 一、交付物分类体系

本项目交付物按"性质 × 战略支柱"二维分类，确保每项交付物有唯一归属、无交叉模糊。

### 1.1 按性质分类

| 类别代码 | 类别名称 | 定义 | 识别特征 |
|---------|---------|------|---------|
| **S** | 软件功能类 | 可运行、可交互的软件功能模块 | 可访问 URL / 可操作交互 / 可独立验证 |
| **A** | 数字资产类 | 图片、视频、模板等静态资源文件 | 文件可直接查看 / 可被软件模块引用 |
| **D** | 文档类 | 文本资料（规范、说明、标准） | 人可阅读、不可执行 |
| **P** | 演示材料类 | 面向观众的成品（视频、脚本、PPT） | 观众可直接观看 / 评委可直接理解 |

### 1.2 按战略支柱分类

| 支柱代码 | 支柱名称 | 覆盖范围 |
|---------|---------|---------|
| **B1** | 管理宠物寄养 | 托管方工具、规范制度、准入准出 |
| **B2** | 沟通宠物家长 | 宠物主端功能、数字孪生、打卡出图 |
| **B3** | 宣传寄养业务 | IP 内容、视频模板、演示脚本 |
| **INF** | 基础设施 | 项目骨架、部署、视觉规范（不归属任一支柱） |

### 1.3 交付物编号规则

```
[Moodmold]-[性质代码]-[支柱代码]-[三位序号]
示例: Moodmold-S-B2-001  = 软件功能类 → B2 沟通家长 → 第 001 号
```

### Moodmold-S-B1-001 — 托管方后台

| 属性 | 内容 |
|------|------|
| **类别** | 软件功能类 |
| **支柱归属** | B1 管理寄养 |
| **优先级** | P0（主链路核心环节） |
| **责任人** | B |
| **交付时间** | Day 2 下午 18:00 |
| **前置依赖** | Moodmold-S-INF-001 |

#### 功能需求

- **身份识别**：托管方可通过特定方式进入后台（与宠物主入口区分）
- **宠物录入**：托管方可录入一只宠物的基本信息（名字、照片、挂牌编号）
- **录入数据持久化**：录入后刷新页面数据不丢失
- **状态更新**：托管方可为已录入的宠物添加状态更新，每次更新包含一段文字描述和一张照片
- **时间线查看**：托管方可按时间倒序查看该宠物所有历史状态更新
- **展示效果**：向宠物主呈现的状态时间线具有自动追踪的观感（实际为托管方手动更新）

#### 验收标准

- [x] 能成功录入一只宠物（名字 + 照片）
- [x] 录入后数据持久化（刷新页面不丢失）
- [x] 能为已录入宠物添加状态更新（文字 + 照片）
- [x] 时间线按时间倒序显示所有更新
- [x] 界面在主流手机屏幕上正常显示和操作

#### 使用场景

- Demo 演示：托管方录入宠物 → 更新状态 → 模拟追踪效果
- 黑客松结束后：展示给潜在合作民宿看工作流

### Moodmold-S-B2-001 — 宠物绑定页

| 属性 | 内容 |
|------|------|
| **类别** | 软件功能类 |
| **支柱归属** | B2 沟通家长 |
| **优先级** | P0 |
| **责任人** | B |
| **交付时间** | Day 1 下午 18:00 |
| **前置依赖** | Moodmold-S-INF-001 |

#### 功能需求

- **扫码进入**：通过扫描挂牌二维码进入（携带挂牌编号参数）
- **品牌展示**：进入后先展示品牌入场动效（约 3 秒），展示产品调性
- **宠物信息绑定**：展示动效后进入绑定表单，宠物主可上传宠物照片并填写宠物名字完成绑定
- **绑定完成跳转**：绑定成功后自动跳转至宠物主查看页
- **已绑定自动跳过**：如该挂牌已绑定过宠物，再次扫码直接跳转查看页，无需重新绑定
- **提交过渡动画**：绑定提交后显示一段加载过渡动画，向用户传达"系统正在为宠物建立数字身份"的感知

#### 验收标准

- [x] 扫码能正确进入绑定页
- [x] 品牌动效展示后自动进入绑定表单
- [x] 照片上传成功且可预览
- [x] 绑定后跳转到宠物主查看页
- [x] 已绑定挂牌再次扫码自动跳过绑定直达查看页
- [x] 绑定提交后的加载过渡动画完整播放

#### 使用场景

- 宠物主第一次扫挂牌 → 绑定宠物信息 → 建立数字身份

- [ ] 至少 2 套挂件可切换
- [ ] 叠加后图片清晰不失真
- [ ] 出图结果可在宠物主查看页展示
- [ ] URL 参数指定景点时能正确触发对应挂件

#### 使用场景

- 托管方更新宠物状态 → 系统自动生成带非遗装扮的打卡照
