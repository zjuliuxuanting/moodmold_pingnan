# Moodmold 黑客松交付物说明书

> 版本 v1.0 | 日期：2026-05-22 | 基于 v0.3 产品战略 + v0.2 技术执行方案
> 本文档是项目交付物的唯一权威定义。所有交付物分类、验收标准、边界划分以此为准。

## 一、交付物分类体系

本项目的交付物按"性质 × 支柱"二维分类，确保每项交付物有唯一归属、无交叉模糊。

### 1.1 按性质分类（横轴）

| 类别代码 | 类别名称 | 定义 | 识别特征 |
|---------|---------|------|---------|
| **S** | 软件技术类 | 可运行代码、部署产物、技术配置 | 有 URL / 可交互 / 可构建 |
| **A** | 数字资产类 | 图片、视频、动画、字体、模板文件 | 文件可直接查看 / 可被代码引用 |
| **D** | 文档类 | Markdown / PDF / PPT 等文本资料 | 人可阅读、不可执行 |
| **P** | 演示材料类 | 视频、脚本、PPT 等面向观众的成品 | 观众可观看 / 评委可理解 |

### 1.2 按战略支柱分类（纵轴）

| 支柱代码 | 支柱名称 | 覆盖范围 |
|---------|---------|---------|
| **B1** | 管理宠物寄养 | 托管方工具、规范制度、准入准出 |
| **B2** | 沟通宠物家长 | 宠物主端产品、数字孪生、打卡出图 |
| **B3** | 宣传寄养业务 | IP 内容、视频模板、演示脚本 |
| **INF** | 基础设施 | 项目骨架、部署、视觉体系（不归属任一支柱） |

### 1.3 交付物编号规则

```
[Moodmold]-[性质代码]-[支柱代码]-[三位序号]
示例: Moodmold-S-B2-001  = 软件技术类 → B2 沟通家长 → 第 001 号
```

### Moodmold-S-B1-001 — 托管方后台

| 属性 | 内容 |
|------|------|
| **类别** | 软件技术类 |
| **支柱归属** | B1 管理寄养 |
| **优先级** | P0（主链路核心环节） |
| **责任人** | B |
| **交付时间** | Day 2 下午 18:00 |
| **前置依赖** | Moodmold-S-INF-001（项目骨架） |

#### 功能范围

- 托管方通过 URL 参数 `?role=host` 进入后台
- **宠物录入表单**：录入宠物名字、上传照片（base64 存 localStorage）、可选备注
- **状态更新面板**：输入文字描述 + 拍照或选择本地图片 → 点击"更新"生成一条时间线记录
- **时间线预览**：托管方可看到自己发布的所有状态记录
- **模拟项圈数据**：展示效果看起来像自动追踪（实际为手动触发）

#### 技术规格

| 项 | 规格 |
|----|------|
| 路由 | `/host` |
| 数据存储 | localStorage，key 为 `moodmold_pets` |
| 图片处理 | FileReader → base64，不调后端 |
| 时间线数据结构 | `{ id, timestamp, text, photoBase64 }[]` |
| UI 适配 | 移动端优先（375px 基准） |

#### localStorage 数据结构

```typescript
interface PetRecord {
  id: string;
  name: string;
  photo: string;        // base64
  tagId: string;        // 挂牌编号
  notes?: string;
  createdAt: string;    // ISO timestamp
  timeline: Array<{
    id: string;
    timestamp: string;
    text: string;
    photoBase64: string;
  }>;
}
```

#### 验收标准

- [ ] 能成功录入一只宠物（名字 + 照片）
- [ ] 录入后数据持久化（刷新页面不丢失）
- [ ] 能为已录入宠物添加状态更新（文字 + 照片）
- [ ] 时间线按时间倒序显示所有更新
- [ ] 界面在 iPhone SE（375px）上正常显示

#### 使用场景

- Demo 演示时：托管方录入宠物 → 更新状态 → 模拟"项圈自动追踪"效果
- 黑客松结束后：展示给潜在合作民宿看工作流

### Moodmold-S-B2-003 — 数字孪生出图引擎

| 属性 | 内容 |
|------|------|
| **类别** | 软件技术类 |
| **支柱归属** | B2 沟通家长 |
| **优先级** | P1（演示华彩段落） |
| **责任人** | B 实现逻辑 + A 提供挂件素材 |
| **交付时间** | Day 2 下午 18:00 |
| **前置依赖** | Moodmold-A-B2-001（挂件素材） |

#### 功能范围

- 托管方上传新照片后，系统自动将预设挂件 PNG 叠加到宠物照片上
- 支持至少 2 套挂件（廊桥小斗笠、古厝戏服）
- 生成结果保存在 localStorage 时间线记录中
- 叠加逻辑为纯前端 Canvas API，不调用后端
- 如当前 URL 包含 `?location=langqiao` 或 `?location=gucuo`，自动选择对应挂件

#### 技术规格

| 项 | 规格 |
|----|------|
| 实现方式 | HTML5 Canvas API（`drawImage` 叠加） |
| 挂件格式 | PNG（透明背景），固定位置叠加 |
| 叠加位置 | CSS 绝对定位坐标预设（每个挂件一个坐标） |
| 输出格式 | base64 PNG |
| 挂件配置 | 从 `/data/overlays.json` 读取 |

#### overlays.json 数据结构

```json
{
  "overlays": [
    {
      "locationId": "langqiao",
      "name": "廊桥小斗笠",
      "src": "/assets/langqiao/overlay.png",
      "position": { "x": 120, "y": 30, "scale": 0.8 }
    },
    {
      "locationId": "gucuo",
      "name": "古厝戏服",
      "src": "/assets/gucuo/overlay.png",
      "position": { "x": 80, "y": 60, "scale": 0.9 }
    }
  ]
}
```

#### 验收标准

- [ ] 挂件能正确叠加到宠物照片上
- [ ] 至少 2 套挂件可切换
- [ ] 叠加后图片不失真
- [ ] 结果可保存并在查看页显示
- [ ] URL 参数 `?location=` 能正确触发对应挂件

#### 使用场景

- 托管方更新宠物状态 → 系统自动生成带非遗装扮的打卡照
- H5 变装打卡模块中，宠物到景点自动换装
