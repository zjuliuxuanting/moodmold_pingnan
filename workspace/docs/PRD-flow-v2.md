# PRD：Moodmold 页面流转逻辑 v2

> 版本：v2 | 日期：2026-05-22 Day 2
> 本文档重新划分"购买前"和"购买后"的页面边界，定义每页入/出口，明确托管方后台需新增的链接入口，并给出完整流转图。
> 基于已有 15 条路由（见 App.tsx），不做删减，仅重组导航逻辑。

---

## 1. 核心理念

**一句话**：购买前走消费者自己操作的线性流程（选民宿-预约-拿通行证）；购买后，所有消费者体验的入口收敛到托管方后台，由托管方模拟"推送消息给宠物主"。

这不是说宠物主不能自己访问，而是在 Demo 演示中，我们以托管方后台为 Hub，展示"托管方更新状态后，宠物主看到了什么"。

## 2. "购买前"和"购买后"页面清单

### 2.1 购买前（Pre-booking）-- 4 页

| 路由 | 页面名称 | 所属支柱 | 角色 |
|------|---------|---------|------|
| `/` | C端品牌首页 | B2 | 消费者 |
| `/stay` | 民宿选择页 | B2 | 消费者 |
| `/book/:innId` | 寄养预约页 | B2 | 消费者 |
| `/pass/:tagId` | 屏南通行证页 | B2 | 消费者 |

**购买前终止标志**：Pass 页面展示完成，宠物主"拿到通行证"。Demo 在此切换到托管方视角。

### 2.2 购买后（Post-booking）-- 11 页

**托管方操作页（3 页）**：

| 路由 | 页面名称 | 所属支柱 | 角色 |
|------|---------|---------|------|
| `/host` | 托管方后台入口 | B1 | 托管方 |
| `/host/checkin` | 录入新宠物 | B1 | 托管方 |
| `/host/update/:petId` | 宠物状态更新 | B1 | 托管方 |

**消费者查看页（6 页，经由托管方后台进入）**：

| 路由 | 页面名称 | 所属支柱 | 角色 |
|------|---------|---------|------|
| `/pet/:tagId` | 宠物数字主页 | B2 | 消费者（托管方预览） |
| `/diary/:tagId` | 屏南日记列表 | B2 | 消费者 |
| `/diary/:tagId/:dayId` | 日记详情 | B2 | 消费者 |
| `/collection/:tagId` | 屏南收藏 | B2 | 消费者 |
| `/card/:tagId` | 寄养纪念卡 | B2 | 消费者 |
| `/pass/:tagId` | 屏南通行证（回看） | B2 | 消费者 |

**辅助页（2 页）**：

| 路由 | 页面名称 | 所属支柱 | 角色 |
|------|---------|---------|------|
| `/bind/:tagId` | 挂牌绑定页 | B2 | 消费者（扫码入口） |
| `/checkin/:tagId` | H5 变装打卡 | B2 | 消费者（P2 占位） |

## 4. 托管方后台需新增的链接入口

### 4.1 `/host` HostPage 需新增

当前 `/host` 只显示：
- 录入新宠物（→ `/host/checkin`）
- 已录入宠物列表（→ `/host/update/:petId`）

**需新增**（每条已录入宠物下方增加操作入口）：

| 新增链接 | 目标路由 | 标签文案 | 优先级 |
|---------|---------|---------|--------|
| 查看主页 | `/pet/:tagId` | "宠物主页" | P0 |
| 查看日记 | `/diary/:tagId` | "屏南日记" | P0 |
| 查看收藏 | `/collection/:tagId` | "屏南收藏" | P1 |
| 纪念卡 | `/card/:tagId` | "寄养纪念卡" | P1 |
| 通行证 | `/pass/:tagId` | "屏南通行证" | P1 |
| H5 打卡 | `/checkin/:tagId` | "变装打卡" | P2 |

建议布局：每条宠物卡片展开后可看到"消费者视图快捷入口"区域（小图标 + 文字横排）。

### 4.2 `/host/update/:petId` HostUpdatePage 需新增

当前 `HostUpdatePage` 包含：
- 添加状态更新（文字 + 照片）
- 已有时更新时间线
- "结束寄养"按钮

**需新增**（页面顶部或底部增加消费者视图快捷入口）：

| 新增链接 | 目标路由 | 标签文案 | 优先级 |
|---------|---------|---------|--------|
| 查看宠物主页 | `/pet/:tagId` | "预览宠物主页" | P0 |
| 查看日记 | `/diary/:tagId` | "预览日记" | P0 |
| 查看收藏 | `/collection/:tagId` | "预览收藏" | P1 |
| 纪念卡 | `/card/:tagId` | "预览纪念卡" | P1 |
| 通行证 | `/pass/:tagId` | "回看通行证" | P1 |

### 4.3 消费者查看页内部需新增的互链

当前消费者查看页（`/pet/:tagId`、`/diary/:tagId` 等）彼此之间没有导航。

**需在 `/pet/:tagId`（宠物主页）新增底部导航区**：

```

│  [宠物数字主页] ← 当前                   │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │

│  └──────┘ └──────┘ └──────┘ └──────┘  │
│  Hero + 时间线 + 出图                    │
│  ...                                    │
│  [分享按钮]                              │
└─────────────────────────────────────────┘
```

**需在 `/diary/:tagId`、`/collection/:tagId`、`/card/:tagId`、`/pass/:tagId` 顶部增加返回导航**：
- 统一的顶部导航栏：返回箭头 + 页面标题
- 返回目标：`/pet/:tagId`

## 6. 是否需删除或隐藏的页面/路由

### 结论：不删除任何路由，但需要隐藏/降级部分入口

| 路由 | 当前状态 | 建议 | 原因 |
|------|---------|------|------|
| `*` → HomePage | Catch-all | 保留不变 | 兜底路由 |
| `/` HomePage | 含开发入口链接区 | **隐藏**开发链接区（或折叠到页面底部"开发者模式" toggle 后） | Demo 演示时消费者不应看到后台入口 |
| `/checkin/:tagId` | 占位页 | 保留，P2 | 未来实现变装打卡 |
| `/bind/:tagId` | 正常工作 | 保留 | 扫码绑定的备用入口 |
| `/diary/:tagId` | 正常工作 | 保留，接入导航 | 无问题 |
| `/diary/:tagId/:dayId` | 正常工作 | 保留 | 无问题 |
| `/collection/:tagId` | 正常工作 | 保留 | 无问题 |
| `/card/:tagId` | 占位/初版 | 保留 | 无问题 |

### 不需要删除任何路由

15 条路由全部保留。需要调整的是：

1. **`/` 首页**：将开发链接区从页面主体移除（折叠到页脚"开发者" toggle），Demo 时默认隐藏
2. **`/pass/:tagId`**：购买前链路终点，"查看日记" CTA 保留但 Demo 中不在此时点击（因为已切换到托管方视角）
3. **所有消费者查看页**：补充顶部返回导航，返回目标统一为 `/pet/:tagId`
